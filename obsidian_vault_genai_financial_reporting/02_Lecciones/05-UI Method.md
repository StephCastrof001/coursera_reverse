## 📜 Transcripción Curada

Bienvenido de nuevo a nuestro curso sobre IA generativa en informes gubernamentales y contabilidad. En el Módulo 2, vamos a discutir los diversos métodos para la implementación de modelos de lenguaje grande, o LLM, en la contabilidad. La comprensión de este método es crucial porque le permite seleccionar el enfoque que mejor se adapte a sus necesidades, capacidades técnicas y presupuesto. Así que, vamos a empezar. La agenda de hoy incluye, en primer lugar, explorar el método de interfaz de usuario o IU. En segundo lugar, comprender el enfoque de Interfaz de programación de aplicaciones, o API. En tercer lugar, presentaré la integración de Automatización robótica de procesos, o RPA, con modelos de lenguaje grande. A continuación, compararé las ventajas y limitaciones de cada enfoque. Por último, hablaré de las tareas de contabilidad adecuadas para cada enfoque. En primer lugar, hablemos del método más sencillo, el uso de la interfaz de usuario, o IU. El método de IU implica interactuar con los LLM a través de una interfaz gráfica proporcionada por el proveedor de servicios. Un ejemplo común es el uso de CheckGPT a través de su interfaz web. Así es como funciona. Para la entrada, usted escribe su consulta o instrucción o pregunta en un cuadro de texto. Para el procesamiento, el LLM procesará su entrada, y para la salida, el LLM generará una respuesta que se mostrará en la pantalla. Este método no requiere conocimientos de programación y es accesible a cualquier persona con una conexión a Internet. Algunas ventajas clave del método IU son, en primer lugar, la facilidad de uso. Es sencillo y no requiere conocimientos técnicos para cualquiera que desee utilizar el enfoque IU. En segundo lugar, las experiencias interactivas. Se pueden mantener conversaciones de ida y vuelta con el LLM y hacer preguntas de seguimiento según sea necesario. Siguiente, fácil de demostrar. Este enfoque es ideal para mostrar la capacidad de los casos a los clientes o miembros del equipo en un entorno en vivo. Por último, no requiere configuración. No es necesario instalar software o configurar un sistema para utilizar el enfoque de IU. Sin embargo, el método de IU tiene varias limitaciones. Primero, baja escalabilidad. IU no es práctico para procesar grandes volúmenes de datos o automatizar tareas repetitivas. Segundo, personalización limitada. IU tiene menos opciones para ajustar parámetros del modelo como la temperatura o la salida máxima del token, etc. Siguiente, hay un token limitado para usar IU. Por ejemplo, hay algunas restricciones en la longitud de entrada y salida que pueden ser problemáticas para documentos largos. Por último, el esfuerzo manual. IU requiere la entrada manual y la copia del resultado a la salida. Esto consume mucho tiempo para las tareas por lotes. Por lo tanto, el método de IU es el más adecuado para varios tipos de tareas. Primero, consultas de clientes. IU es mejor para responder a las consultas de los clientes de forma interactiva. Siguiente, análisis financiero básico. Usted puede hacer cálculos rápidos o interpretaciones utilizando IU para su análisis financiero básico. Siguiente, comprobaciones de cumplimiento. Puede verificar información específica en un documento con la IU. Por último, fines educativos. Puede hacer demostraciones y formar a su cliente con la IU. En general, es ideal cuando el volumen de tareas es bajo y requiere juicio e interacciones humanas. Es todo por la conferencia de hoy. En la próxima conferencia, presentaremos el enfoque API en detalle. Gracias por vernos.
